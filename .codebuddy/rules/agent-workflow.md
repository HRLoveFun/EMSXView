# Agent 工作流规则（作业节奏与等待）

> 定位：约束 AI 代理（CodeBuddy / Claude Code / Cursor 等）在本仓库**执行作业时的等待与轮询行为**。
> 与 [`docs/spec/git-workflow.md`](../../docs/spec/git-workflow.md)（多任务并行 / worktree / hooks / 并发纪律）互补：本文件只管「等待节奏」，其余不重复、不另立规则。

---

## 1. 等待与轮询节奏（★ 每 5 秒一次）

**凡需要等待外部状态变化后再决策的步骤，一律每 5 秒检查一次**：既不用更长间隔空转，也不无间隔忙等。

| 场景 | 规范命令 |
|---|---|
| PR 的 CI 门禁 | `gh pr checks <编号> --watch --interval 5` |
| 先判断检查是否已启动 | `gh pr checks <编号>`（不阻塞；未启动则 5 秒后重查） |
| Actions run 详情 | `gh run watch <run-id> --interval 5` |
| 服务 / 端口 / 进程就绪 | 5 秒间隔轮询至就绪或超时 |

约束：

- 轮询一律用**只读**命令；拿到一次完整结果后再决策，不在等待过程中穿插写操作。
- 以**退出码**作为门禁判定（`gh pr checks --watch` 全绿才继续合并），不靠人工目测输出。
- 超时仍未到终态时，报告当前状态并停止等待，不无限空转。

---

## 2. 等待期间的纪律

- 等待期间**不得**修改工作树（尤其禁止穿插 `git add` / `git commit`），避免与他人在途作业交错。
- 连续多次轮询仍为 `pending`，且已明显超过该 Job 的历史耗时（前端 ≈40s、后端 ≈40–50s、清理门禁 ≈10s、边界审计 ≈15s）时，先取一次 run 详情再决定是否继续等待。
- 合并、删除分支、删除 worktree 等动作的约束仍见 [`docs/spec/git-workflow.md`](../../docs/spec/git-workflow.md) §5、§9、§10（破坏性动作永不自动）；同目录并发与会话独占锁见同文件 §4.8、§10。
