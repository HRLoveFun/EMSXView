## 2. P1：阈值与列口径错配

### 2.1 代码

```356:364:CostView/src/tca_utils.py
def bucket_volatility(daily_volatility: Optional[float]) -> tuple[str, str]:
    """Bucket daily volatility in percent space."""
    if daily_volatility is None:
        return ("unknown", "Unknown")
    if daily_volatility < 1.5:
        return ("calm", "Calm (<1.5%)")
    if daily_volatility < 3.5:
        return ("typical", "Typical (1.5%-3.5%)")
    return ("stressed", "Stressed (>=3.5%)")
```

`1.5%` / `3.5%` 是**日**波动率的典型区间；docstring 里的「percent space」是**假定**，从未被校验。

### 2.2 入参来源（本仓库 4 跳，中间无任何换算）

| 跳 | 位置 | 行为 |
|---|---|---|
| 1 | `tca_utils.cohort_key_and_label`（`:210`） | 分发 |
| 2 | `_env_cohort_key` 的 `volatility` 分支（`:201-206`） | 真实字段**原值直传**；缺失才回退 `abs(pnl_vwap)` 代理 |
| 3 | `env_context.RouteEnvContext.daily_volatility` | 每路由一个值 |
| 4 | `build_route_env_context`（`env_context.py:159-190`）→ `load_daily_env`（`:124-149`） | 应用层 join；SQL：`SELECT equ_ticker, trade_date, adv_20d, daily_volatility FROM bdib_daily_summary` |

### 2.3 列的实际量纲（反推）

对每个交易日计算 `daily_volatility / (std(滚动 N 日对数收益率) × 100)`：

| Ticker | N=10 | N=20 | N=30 | 期望值 |
|---|---|---|---|---|
| NVDA US | 15.65 | 15.77 | **15.96** | **15.87 = √252** |
| 7203 JP | 14.00 | 13.83 | 13.49 | 15.87 |
| BHP AU | 16.36 | 16.20 | 16.22 | 15.87 |

比值 ≈ √252 而非 ≈ 1 → **该列是年化百分比**：

```
daily_volatility = std(滚动窗口日对数收益率) × √252 × 100
```

**逐月验证**（6 个大盘标的、12 个月）比值稳定在 13~17，无异常月份：

```
202510 15.796 | 202511 16.698 | 202512 16.610 | 202601 13.113
202602 14.070 | 202603 16.217 | 202604 15.917 | 202605 15.680
202606 14.459 | 202607 16.353 | 202608 16.023 | 202609 16.995
```

**未能唯一确定**：窗口长度（N=20 与 N=30 的比值都接近 √252）与收益率类型（log / pct）。
二者不影响量纲结论。

### 2.4 分布与分桶后果

`bdib_daily_summary.daily_volatility`（`20250901`~`20260901`，214,030 条非空）：

| 统计量 | 值 |
|---|---|
| 中位数 | **26.075** |
| p25 / p75 | 17.31 / 37.90 |
| p05 / p95 | 0.380 / 70.05 |
| min / max | 0.0226 / 950.44 |

按现有阈值直接入桶：`calm(<1.5) 16.47% | typical(1.5~3.5) 0.61% | stressed(>=3.5) 82.92%`

**判据**：个股「日波动率 26%」意味年化约 413%（不存在）；「年化 26%」是常态 → 该列确实是年化。

## 3. P2：同一列两种量纲

### 3.1 决定性证据：同标的跨时段跳变

| ticker | 其它月份中位 | 202603 | 202604 | 后续 |
|---|---|---|---|---|
| `1942 JP Equity` | 202602: **43.566** | 0.435 | 0.398 | **202607: 45.917**（恢复） |
| `011790 KS Equity` | 202509: **33.006** | 0.672 | 0.723 | — |
| `097950 KS Equity` | 202509: 26.287 / 202510: 14.281 | 1.110 | 1.091 | — |
| `2269 JP Equity` | 202511: 15.634 | 0.308 | 0.276 | — |
| `2897 JP Equity` | 202511: 22.932 | 0.294 | 0.264 | — |

`43.566 → 0.435 → 45.917` 说明：**不是该标的天生用小数，而是在 2026-03~04 被写成小数，随后写回百分比**。

### 3.2 区间分布

按月份统计 `daily_volatility < 1.5` 的行占比：

| 月份 | 行数 | min | `<1.5` 占比 |
|---|---|---|---|
| 202509~202602 | — | 1.16 ~ 7.85 | ≈0% |
| **202603** | 40,219 | **0.0226** | **54.8%** |
| **202604** | 22,586 | **0.033** | **58.5%** |
| 202605~202609 | — | 1.23 ~ 2.62 | ≈0% |

### 3.3 为什么不是「某市场用另一套单位」

按市场统计 `<1.5` 占比是**分散**的（IN 37.6% / KS 36.3% / SJ 37.4% / MK 33.0%，
而 HK / CN / BZ / DC 为 0%），跨市场命中 —— 与区间解释一致。

### 3.4 两次误判的修正记录（保留，避免后续再走弯路）

1. 起初据「按月集中」推断为**月份问题**；
2. 随后用 6 个**大盘标的**逐月验证（12/12 个月正常），据此推翻了该推断 —— 但抽样只覆盖
   了「当时未被重写的标的」，属**抽样偏差**；
3. 最终以**同标的跨时段跳变 + 后续恢复**为判据，确认是**区间性的写入问题**。

结论：**上游在 2026-03~04 写入该列时使用了年化小数（缺 ×100），其余时段为年化百分比。**

成因**未证实**（本仓库看不到上游计算与调度）：**推测**为该时段数据由另一条计算/回填路径产出，
两条路径对「百分比 / 小数」的处理不一致。需跨仓核对。

## 5. 日内区间波动率字段的核实（用户提问项）

**字段存在，且分两处**：

| 字段 | 表 | 粒度 | 值域（实测） | 非空率 |
|---|---|---|---|---|
| `intraday_volatility` | `bdib_daily_summary` | 标的 × 日 | 0 ~ 15.27（中位 ~0.5~2） | **38.7%** |
| `cum_interval_volatility` | `fill_bdib` | 标的 × 路由 × 时点 | 0 ~ 37.77（avg 0.234） | 31.8%（2,123,473 / 6,680,277） |
| `standard_cum_interval_volatility` | `fill_bdib` | 同上 | 0 ~ 127.33（avg 0.922） | 31.8% |

**是否已换算成年化：否。** 判据 —— 同一 `(ticker, trade_date)` 上
`intraday_volatility / daily_volatility` 的比值（`20251001`~`20260228`，n=1,454）：

```
中位 0.0149   p10 0.0086   p90 0.0275      对照 1/√252 = 0.0630
```

> ⚠️ **本节结论已被上游核实推翻（2026-09-22），保留原文与更正如下** ——
> 我当时用的判据是 `intraday / daily`，**没有对齐单位**：`daily_volatility` 是
> **百分比**口径（Bloomberg `VOLATILITY_30D`），而 `intraday_volatility` 是**小数**口径，
> 两者直接相除得到的 0.0149 只反映「百分比 ÷ 小数」的单位差，不反映年化与否。
>
> **正确判据**：`intraday_volatility / (daily_volatility / 100)` —— 本侧复测中位
> **1.2501**（上游 n=84,209 报 1.2800），即**两列同为年化口径**，比值 ≈1.25 属
> 「日内 bar 级波动略高于日间」的合理形态。若 intraday 未年化，该比值应 ≈ 1/√252 = 0.063。
>
> 上游代码依据（`daily_metrics_calculator.py`）：
> `intraday_volatility = std(10 秒对数收益率) × sqrt(BARS_PER_YEAR)`，
> `BARS_PER_YEAR = 252 × 6.5 × 3600 / 10 ≈ 589,680` —— 即**年化**，且因 `std` 为小数而
> 呈**小数形态**。
>
> 结论更正：`intraday_volatility` **已年化（小数）**；旧阈值 1.5/3.5 对它并**不**适用，
> 若将来启用该列需先 ×100 转百分比。
>
> **`fill_bdib` 两列的量纲已由上游核实（2026-09-22，第三轮）**：
>
> - `log_chg_pct_10s` 实为**小数**对数收益（生成式 `ln(close/close.shift(1))`）——
>   上游文档原文标注为「%」**有误**，已更正；
> - `cum_interval_volatility` = 其**未年化**的 expanding std（小数）；
> - `standard_cum_interval_volatility` = 前者 ÷ 该批次**全表非零均值** ——
>   **无量纲，且跨批次不可比**（不同批次的归一化基数不同）。
>
> **另登记一个上游潜在缺陷（其未改动，待设计确认）**：`compute_derived_fields` 计算
> `log_chg_pct_10s` 时使用**未分组**的 `shift(1)`，而调用方传入的是多 ticker 合并
> DataFrame —— 每个 ticker 当日的**首个 bar** 会与**上一个 ticker** 的末 bar 相除，
> 且结果依赖 chunk 划分（**不可复现**）。若将来启用这两列，需先由上游修此分组缺陷。

> ⚠️ **以下「含义」段已作废** —— 它建立在「日内列未年化」这一已被推翻的前提上：
>
> ~~若要用日内波动率做分层，不需要再年化，而是要与 `bucket_volatility` 的日内阈值
> （1.5% / 3.5%）配套 —— 即当前阈值空间对 `intraday_volatility` 是合适的。~~
>
> **更正后**：库内**没有任何「日波动率」口径的列**（两列均为年化）。若要构造日波动率
> 分层，需自行折算（`daily_volatility / √252`），且该折算属本侧新增口径，须进
> `report_spec` 声明。

## 7. 修复方向（依本文证据，**部分已被 §7b 取代**）

1. **单位统一（修 P2 的表象）**：在**数据入口单点**（`env_context`）把小数写法归一化为百分比。
   依据：正常年化百分比 ≥ 5、正常年化小数 ≤ 2，中间 **2~5 近乎空档** → 以 **3.0** 为界安全。
   命中必须**可见**（计数 + 区间标记随 payload 披露），不得静默修数。
2. **阈值对齐（修 P1）**：`bucket_volatility` 阈值改为年化空间，与 `market.py` 的 25 / 40 一致，
   标签文案同步（`<25% 年化` 等）。
3. **跨仓项**：请上游确认 `daily_volatility` 权威定义，并修正 `202603` / `202604` 的量纲。
