| # | 坑 | 正确做法 |
|---|---|---|
| 1 | 后端 + MarketView/CostView 测试**同进程跑** → conftest sys.path 交叉，全部 collection error | **分进程**跑各域测试（与 CI 一致） |
| 2 | 前端 worktree 用 junction 共享主树 `node_modules` → `.bin` 解析失败、`npx` 联网被拦 | 含前端改动时**接受 CI 迭代**（本地 typecheck 用 `node <主树>/node_modules/typescript/bin/tsc -b`；vitest 交 CI） |
| 3 | AP-08 把「含下划线的契约子模块名」（`access_policy`/`order_split`/`strategy_registry`）误判为下划线访问 | 一律 `from platform_data.contracts import ...`（包入口），禁止深层子模块 import |
| 4 | `write_to_file` 偶发假落盘（返回 success 但文件未写） | 写完大文件/提交前 `Test-Path` 或跑一次 import 验证 |
| 5 | 主树 100 个文件曾被误删（工作区丢失、HEAD 完好） | 判断标准：HEAD blob 完好 + 无替代 + 目录 mtime 同秒 → `git checkout -- <path>` 恢复；**未核实前不要 `git add -A` 提交** |
| 6 | safe-delete 机制拒绝 `Remove-Item`/`wt-clean`（`trash-failed`） | 找占用进程（`Get-Process python`）先终止；仍失败则记录残留待人工删，不反复重试 |
| 7 | `node_modules` 为 junction 时 `Remove-Item -Recurse` 可能穿透删目标 | 先 `[System.IO.Directory]::Delete($junctionPath)` 解链再删目录 |
| 8 | 主树可能被其他会话持有 git 索引锁（hook 警告） | 主树只做集成（pull/清理）；开发一律在 worktree；看到锁警告不要 add/commit |
| 9 | SQLite `date()` 只认 `YYYY-MM-DD`，EMSX 用 `YYYYMMDD` | 跨库时间比较前先归一化（`_iso_date`） |
| 10 | `getByText` 对「单元素多文本节点」匹配失败 | 徽标类测试用正则匹配器或 `getAllByText` |
| 11 | `*.xlsx` 被 gitignore → 测试夹具静默丢失 | 精确路径例外（`.gitignore` 末尾 `!path/*.xlsx`） |
| 12 | 半日市/竞价/午休三个时间概念易混 | 午休不改窗口边缘；竞价是窗口终点；半日市**同时**收缩收盘与竞价时刻（074 固化） |
