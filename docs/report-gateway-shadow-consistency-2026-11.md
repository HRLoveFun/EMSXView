## 1. 结论

1. **99.9% 的目标只对 `VWAP` 成立，不能推广到三个字段。** `CHG_PCT_1D` 与 `VOLUME_AVG_5D` 在本机两侧都没有推送值（`both_missing`），没有可比样本，一致率只能是 `null`；把它们算进分母会把一致率稀释到 70% 左右，看起来像网关错，实际是覆盖度问题。
2. **修复后（2026-11-11 20:48 起）VWAP 精确相等率 100%**：20:48–13:59 窗口 19,100 条 `both_present` 全部 `exact`，`value_diff` 为 0；2026-11-12 00:00–00:20 另有 1,350 条同样 100% `exact`。
3. **修复前的 158,356 条 `value_diff` 全部是 VWAP**，不是网关算错数，而是**两侧拿到不同时刻的 VWAP**：89.2% 的样本可定位为「网关值 = 更早的 direct 值」，中等偏移 **−55.7 秒**（p25 −70.2s / p75 −39.3s）；另有 1.3% 是网关返回 `0.0`（无成交/未开盘的占位值），应按缺失处理。
4. **修复前的一多半样本被重复采样放大**：2026-11-11 20:23 之前存在 6 个并行采样线程，单日 1,657,721 条样本中约 6 倍冗余（见 PR #239）。因此修复前的比率只作定性参考，不作取证数字。

## 2. 口径

| 概念 | 定义 | 为什么 |
| --- | --- | --- |
| `both_missing` | 两侧都无值 | 不进 `match_rate` 分母；否则「两侧都无 = 一致」会把一致率抬到 100% |
| `both_present` | 两侧都有值 | 一致率的唯一分母 |
| `matched` / `exact` / `near_match` | 一致 / 数值完全相同 / 仅落在 1e-6 相对容差内 | 容差内一致不等于同一 tick，必须分开报 |
| `reasons` | `value_diff` / `gateway_missing` / `direct_missing` | 缺数据与值不同不能混算 |
| `by_lag` | 按 `gateway_recv_ts` 与采样时刻之差分层（≤5s / 5–30s / >30s / 未知） | 同一时点级别内的一致率才说明「同一 tick 是否算对」 |
| `value_diff` | 不一致样本的 `\|rel_diff\|` 分位 | 区分末位误差与量级差异 |

## 7. 局限与上游待办

1. **网关不提供事件时间戳**：`gateway_src_ts` 恒为 `null`，无法按 tick 对齐，只能靠 `recv_ts` 与插值推断；建议上游 `emsx-gateway` 增加字段级事件时间。
2. **`gateway_recv_ts` 的语义是「网关最近一次收到该值的时刻」**，静态标的会自然变大（实测 >3 小时），不能直接当「延迟」读；判定延迟要看活跃标的。
3. **网关 `0.0` 与「无值」**未区分：建议上游用显式缺失码替代 0 占位，否则每次开盘前都会被记成一次不一致。
4. 修复前数据含 6 倍重复采样，比率只能定性；取证的定量结论只应引用修复后窗口。
