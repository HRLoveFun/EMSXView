### 🔴 P0a: 存储分层体系 (Storage Tiering)

> **关联**: 项目功能构建规划 §11 | 数据规模 88GB 且日增 600MB

#### 现状

| 指标 | 值 |
|------|-----|
| 数据日期范围 | 2025-09-25 → 2026-04-22 (147 trading days) |
| 活跃 ticker 数 | ~1989 |
| `raw_bdib.db` | 68.5 GB (78%) |
| `processed_fills.db` | 14.6 GB |
| 其他 DB | ~5.4 GB |
| **总计** | **~88 GB** |
| **日增量** | **~600 MB/trading day** |
| **年增量预估** | **~150 GB/year** |
| 本地磁盘 | 1 TB (剩余 ~932 GB) |

#### 问题分析

- 单库 68.5 GB 导致查询性能持续下降
- 无冷热分层，每次 attribution 计算全量扫描
- 年度 150 GB 增量不治理，12 个月内将逼近磁盘上限
- 所有新模块（regime、attribution）仍直接读 SQLite，无统一路由层

#### 改进内容

```
存储分层: Hot (SQLite, ≤12 个月) + Cold (Parquet 分区归档)
```

| 层级 | 范围 | 格式 | 路径 |
|:----|:-----|:-----|:-----|
| **HOT** | 最近 12 个自然月 | SQLite | `CostView/data/*.db` |
| **COLD** | >12 个月历史 | Parquet (按 year/month 分区) | `CostView/data/archive/year=YYYY/month=MM/` |

#### 实施步骤

| 步骤 | 内容 | 预估工期 |
|:----|:-----|:--------|
| 1 | 新建 `CostView/src/storage/` 包，含 `tiering_config.py`、`parquet_archive.py` | 2 天 |
| 2 | 实现 `unified_reader.py` — 统一查询接口（Hot/Cold 自动路由） | 3 天 |
| 3 | 实现 `archive_manager.py` — 月度归档主流程（SQLite → Parquet 转储） | 3 天 |
| 4 | 实现 `archive_audit.py` — 归档审计表 + 校验（hash 验证完整性） | 1 天 |
| 5 | 单月数据迁移演练（选 2026-01 月数据验证流程） | 2 天 |
| 6 | 全面迁移历史数据 + 集成测试 | 3 天 |
| 7 | 更新 `__main__.py` 添加 `archive` CLI 命令 | 1 天 |
| **总计** | | **15 天** |

#### 预期效果

| 指标 | 改进前 | 改进后 | 改善幅度 |
|:-----|:------:|:------:|:--------:|
| Hot 区单库大小 | 68.5 GB | ≤25 GB | **-63%** |
| 查询冷数据速度 | 全表扫描 | 分区裁剪 | **3-10x** |
| 磁盘使用增速 | 600 MB/日 | 受控 | **可控** |
| 研究复现能力 | 依赖 SQLite 快照 | 独立 Parquet 目录 | **可复现** |
| 新模块数据访问 | 直连 SQLite | UnifiedReader | **可切换** |

| 不变量 | 适用模块 | 保护方式 |

| 处理后的日期一定有对应的输出表 | pipeline | 测试 |
| 归因指标 bps 在合理范围内 (±10000 bps) | attribution/metrics | assert |

```
异常层次: 基础异常 → 领域异常 → 模块异常
```

#### 实施步骤

| 步骤 | 内容 | 工期 |
|:----|:-----|:----|

| 3 | 在 Repository 层使用精确异常替换泛化 Exception | 1 天 |
| 4 | 在 API 层添加异常→HTTP 状态码映射 | 1 天 |
| 5 | 更新测试验证异常行为 | 0.5 天 |
| **总计** | | **3.5 天** |

#### 异常层次设计

```
EmsxError (Base)
├── DataError
│   ├── DataNotFoundError
│   ├── DataIntegrityError
│   └── DataValidationError
├── PipelineError
│   ├── StageExecutionError
│   └── PipelineAbortError
├── StorageError
│   ├── ConnectionError
│   └── MigrationError
├── ConfigError
│   ├── MissingConfigError
│   └── InvalidConfigError
├── ApiError
│   ├── AuthenticationError
│   └── AuthorizationError
```

#### 预期效果

| 场景 | 改进前 | 改进后 |
|:-----|:-------|:-------|
| DB 查询失败 | `raise Exception("query failed")` | `raise DataNotFoundError(ticker, date)` |
| API 错误响应 | 500 + 无结构化信息 | 4xx/5xx + 错误码 + 结构化 body |
