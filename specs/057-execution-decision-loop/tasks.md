# 057 子任务清单（DL-01 至 DL-28）

> 伞计划：[`plan.md`](plan.md)。DL 编号即执行顺序。每项含 G1 三栏（理论依据 / 技术方案 / 检验方法）与预留接口；**检验方法即该子任务的验收标准**。
> 状态以本文件为准，由各子任务 PR 随代码一起更新。

## 开工规程

一个 DL 对应一个子编号、一个 worktree、一个分支、一个 PR。子编号是三位数字（从 058 起）；feature-id 是子编号加 slug（如 `058-export-intent-parser`），worktree、分支与 `specs/` 目录都用它（`docs/spec/git-workflow.md` §2）。派工由用户在主工作树完成，执行由 Agent 在 worktree 内完成（同文 §7：一个 Agent 绑定一个 worktree）。

### 派工（用户，主工作树）

1. **选条目**：从状态总览挑依赖已全部完成的条目；第一波是 DL-01 与 DL-02 并行（`plan.md` 第 11 节）。同时派多个时，先对比各自的预计改动文件，重叠大的改为串行（同文 §7.6）。
2. **定子编号**：取 `specs/` 与本地分支中的最大编号加 1，配 2–4 个英文词作 slug。同时派多个就依次加 1，由派工人一次分配，避免两个 Agent 算出同一个编号。
3. **建 worktree 并开会话**：运行 `./scripts/devtools/wt-new.ps1 <feature-id>`，在 `../EMSXView-wt-<feature-id>` 打开新的 Agent 会话，发下方的开工指令。

### 执行（Agent，worktree 内）

4. **读**：确认当前分支（`git branch --show-current`）；按 `AGENTS.md` §1 读完必读文档；读 `plan.md` 全文，以及本文件的目标条目和它依赖的条目。
5. **写子规格（G1）**：新建 `specs/<feature-id>/plan.md`，沿用 030–048 的单文件写法。抬头写父计划（本伞计划的 DL-xx）、分支与依赖；正文分问题、方案（P2 三栏）、范围锁、验收（P4）四节。三栏与验收取自本文件条目，只细化到文件与函数，不扩范围。写完先停下等用户确认；发现条目本身有错或有缺口时也停下报告，计划修订单独走 docs PR，不夹带在实现 PR 里。子规格不走 `/speckit.specify`：它会另生成 spec.md，其建分支钩子也会与 worktree 已有的分支冲突。
6. **实施（G2）**：只改范围锁内的文件；新能力默认关闭，开关在 Config 声明（宪法 IV）；测试按「检验方法」写；夹具只用虚构或脱敏数据（公开仓库）。单 PR 建议 ≤200 行 diff，超出时拆成多个子编号，各自一个 PR。
7. **交付（G3）**：`wt-sync.ps1` 同步并跑相关测试，压成一个提交（同文 §4.8），push 后开 PR。标题形如 `feat: <摘要> (057-DL-01/058)`，描述逐条对照「检验方法」给证据。同一 PR 内把状态总览该行改为「已完成」并填子编号；squash 合并的提交标题会带上 PR 号，用 `git log --oneline --grep "057-DL-01"` 可查。几个并行 PR 都改状态表时，后合并的那个 rebase 会在相邻行冲突，两边都保留即可。合并后用户在主工作树运行 `wt-finish.ps1 <feature-id> -DeleteBranch`。
8. **管道侧条目**：标「管道仓库实施」的条目在 EMSXDataPipeline 仓库按其规范实施；本仓库只做契约镜像、只读适配器与复验，并在管道改动后同步 `docs/EMSXDataPipeline-TECHNICAL_GUIDE.md` 副本。

## 1a 接入与契约

### DL-01 EMSX 导出解析与 PM 意图映射（只读 MVP）

- 风险：低 · 预估：1.5 周 · 依赖：无
- 需求：R1 交易前检测、R2 约束分配、R3 科学评估 · 模块：MarketView、platform_data
- **理论依据**：意图决定算法族与评估口径，必须在决策时点取得；PM Note 13 只能从 EMSX 手工导出获得（D-1），导出快照事后无法重建
- **技术方案**：收件箱目录在仓库外，导出文件只增不删（留档）；按列名解析，重复列名按出现顺序加后缀，8 个可能受限的基准列按可选处理，缺关键列或字段数与表头不符时报错可见；PM Note 13 按第一个 ^ 切开：前缀定意图（VWAP、CLOSE、MIX 含收盘比例、SPECIAL、UNMAPPED），^ 段作连接键，与订单级 notes 字段（EMSX_NOTES）匹配，不用路由级同名字段；映射表带版本；盘前单 v0 读最新一份导出、直接展示现成字段；DL-07 上线后改读 order_intent 表，删除直读路径
- **检验方法**：以附录脱敏样例为金标准底稿：夹具中 PM Note 13 填虚构连接键，覆盖无前缀、100 % @Close、80 % @Close、Spec.Instr.、未知前缀五种写法，被星号遮蔽的数值列填虚构数值；原样遮蔽版测试遮蔽值与受限值按缺失处理；异常用例：缺列、字段数错位、列序变化、空 PM Note；连接覆盖率与未匹配清单在盘前单可见
- **预留接口**：OrderIntent 契约 v1（order_key、benchmark、close_pct、raw_note、intent_source、valid_from、export_ts）；解析规则与金标准样例供 DL-07 管道侧实现对齐

### DL-07 管道盘中作业 J1：成交增量、导出入库、运营库采集（管道仓库实施）

- 风险：中低 · 预估：1.5 周 · 依赖：DL-02、DL-05、DL-06
- 需求：R0 数据即时化、R1 交易前检测、R3 科学评估 · 模块：上游管道（EMSXDataPipeline）
- **理论依据**：自己的执行数据（成交、意图、路由参数）不占行情额度，分钟级更新成本低；盘前单盘中刷新与当日临时 TCA 都依赖它
- **技术方案**：新增盘中调度进程（由 `bootstrap.ps1` 拉起并纳入健康检查，按市场开关），约 5 分钟一轮：GetFills 按 UTC 时间窗从水位增量拉取，按交易所本地 order_as_of_date 归属（拉取日 ≠ 交易日），复用 S2 清洗与 S3 10 秒聚合写 intraday_fills，未知交易所的行隔离告警、不阻断整轮；GetFills 当日不可得时退回运营库路由快照（累计成交量与均价的变化）生成粗粒度临时成交；扫描收件箱，导出写 blotter_snapshots，意图写 order_intent（按导出时间留版本）；只读打开运营库，每轮用短事务采集订单状态（含订单级 notes 与 sequence 的对应，用来把意图连到订单）与路由参数写 route_params_snapshot；不写 raw_fills 与 fetch_log；全局 quota_pause 置位时让路，自身遇额度错误只停盘中作业（独立标记）；Bloomberg 拉取段与日更互斥；每轮写新鲜度清单
