## 开工规程

一个 DL 对应一个子编号、一个 worktree、一个分支、一个 PR。子编号是三位数字（从 058 起）；feature-id 是子编号加 slug（如 `058-export-intent-parser`），worktree、分支与 `specs/` 目录都用它（`docs/spec/git-workflow.md` §2）。派工由用户在主工作树完成，执行由 Agent 在 worktree 内完成（同文 §7：一个 Agent 绑定一个 worktree）。

### 派工（用户，主工作树）

1. **选条目**：从状态总览挑依赖已全部完成的条目；第一波是 DL-01 与 DL-02 并行（`plan.md` 第 11 节）。同时派多个时，先对比各自的预计改动文件，重叠大的改为串行（同文 §7.6）。
2. **定子编号**：取 `specs/`、`docs/archive/` 与本地分支中的最大编号加 1，配 2–4 个英文词作 slug。同时派多个就依次加 1，由派工人一次分配，避免两个 Agent 算出同一个编号。
3. **建 worktree 并开会话**：运行 `./scripts/devtools/wt-new.ps1 <feature-id>`，在 `../EMSXView-wt-<feature-id>` 打开新的 Agent 会话，发下方的开工指令。

### 执行（Agent，worktree 内）

4. **读**：确认当前分支（`git branch --show-current`）；按 `AGENTS.md` 文档地图的「何时读」列取文档（开工前至少读：本文件、`plan.md`、`docs/spec/project-structure.md`、`.codebuddy/rules/module-boundary.md`）；读 `plan.md` 全文，以及 `dl-specs.md` 中目标条目和它依赖的条目。
5. **写子规格（G1）**：新建 `specs/<feature-id>/plan.md`，沿用 030–048 的单文件写法。抬头写父计划（本伞计划的 DL-xx）、分支与依赖；正文分问题、方案（P2 三栏）、范围锁、验收（P4）四节。三栏与验收取自 `dl-specs.md` 条目，只细化到文件与函数，不扩范围。写完先停下等用户确认；发现条目本身有错或有缺口时也停下报告，计划修订单独走 docs PR，不夹带在实现 PR 里。子规格不走 `/speckit.specify`：它会另生成 spec.md，其建分支钩子也会与 worktree 已有的分支冲突。
6. **实施（G2）**：只改范围锁内的文件；新能力默认关闭，开关在 Config 声明（宪法 IV）；测试按「检验方法」写；夹具只用虚构或脱敏数据（公开仓库）。单 PR 建议 ≤200 行 diff，超出时拆成多个子编号，各自一个 PR。
7. **交付（G3）**：`wt-sync.ps1` 同步并跑相关测试，压成一个提交（同文 §4.8），push 后开 PR。标题形如 `feat: <摘要> (057-DL-01/058)`，描述逐条对照「检验方法」给证据。同一 PR 内把状态总览该行改为「已完成」并填子编号；squash 合并的提交标题会带上 PR 号，用 `git log --oneline --grep "057-DL-01"` 可查。几个并行 PR 都改状态表时，后合并的那个 rebase 会在相邻行冲突，两边都保留即可。合并后用户在主工作树运行 `wt-finish.ps1 <feature-id> -DeleteBranch`。
8. **管道侧条目**：标「管道仓库实施」的条目在 EMSXDataPipeline 仓库按其规范实施；本仓库只做契约镜像、只读适配器与复验，并在管道改动后同步 `docs/EMSXDataPipeline-TECHNICAL_GUIDE.md` 副本。

**开工指令模板**（替换 DL 编号与 feature-id 即可）：

```text
你在 worktree ../EMSXView-wt-058-export-intent-parser（分支 058-export-intent-parser）中工作，任务是 specs/057-execution-decision-loop 伞计划的 DL-01，子编号 058。
1. 先确认当前分支；按 AGENTS.md 文档地图的「何时读」列取文档；再读 specs/057-execution-decision-loop/plan.md 全文，以及 dl-specs.md 中 DL-01 和它依赖的条目。
2. 按 tasks.md 开工规程第 5 步写 specs/058-export-intent-parser/plan.md，只细化条目、不扩范围。写完先停下等我确认。
3. 确认后按范围锁实施：新能力默认关闭，测试按条目「检验方法」写，夹具只用虚构或脱敏数据，单 PR 不超过 200 行。
4. 交付：压成一个提交，PR 标题带 (057-DL-01/058)，描述逐条对照检验方法给证据；同一 PR 内把 tasks.md 状态总览的 DL-01 改为「已完成」并填子编号。
```
